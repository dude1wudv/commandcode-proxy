## 差异与实现

官方 CLI 1.88.2 新增 `isRefusalFinishReason` / `consumedStopReason`，识别 `refusal`、`content_filter`、`content-filter`，同时检查终局事件的 `rawFinishReason` 与 `finishReason`。原代理忽略 raw reason，可能把内容过滤写成正常 stop；零输出拒绝也会误报成可重试 429。

本次统一三类兼容入口的流式和非流式处理：Chat 返回 `finish_reason=content_filter`；Messages 返回 `stop_reason=refusal`；本地转译 Responses 返回 `status=incomplete`、`incomplete_details.reason=content_filter`。仅对明确拒绝终态免除零输出错误，保留已知输入、缓存和输出用量；普通空流与断流继续原错误策略。原生 Provider Responses 透传链路未修改。

官方 `consumeStream` 只从 `type=finish` 读取终态，完全不处理旧兼容事件 `finish-step`。本代理仍接收旧事件，但后续终局 `finish` 为准：旧 step 的拒绝不会覆盖最终 stop；终局无 reason 时按官方默认正常结束；终局 raw refusal 也不会再被旧 step 的 stop 遮盖。新增回归覆盖这些方向。

协议版本固定为经核对的 `1.88.2`，生成请求、初始化请求和 lifecycle metadata 使用同一版本；后续 npm 漂移仍只告警，不自动修改声明版本。
